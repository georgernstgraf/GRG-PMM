Warum ein Skript statt Taschenrechner?

R und RStudio verstehen, ein Projekt anlegen — und den ersten eigenen R-Skript schreiben, der in einem Jahr noch läuft.

Lektüre

R4DS 2e (englisch): Kap. 6 — Workflow: scripts and projects und Kap. 2 — Workflow: basics. Lies beide Kapitel vor der Aufgabe — die Fragen beziehen sich darauf.

Einstiegsfrage

Eine Kollegin hat 120 Teile vermessen: drei Maschinen, Sollmaß 10,00 mm, Toleranz ± 0,15 mm. Nächste Woche will die Produktionsleitung dieselbe Auswertung noch einmal — mit einer neuen Charge.

Mit dem Taschenrechner heißt das: 120 Werte eintippen, Quadrate, Summen, Wurzel — pro Maschine. Und nächste Woche alles von vorn.

Muss das sein? Nein: Es gibt ein Werkzeug, das die Rechnung behält und nächste Woche mit einem Klick wiederholt.

Ziel-Artefakt

Das ist das Ergebnis, das du am Ende dieser Doppelstunde selbst erzeugst: ein winziges Projekt, in dem ein Skript die Kennzahlen jeder Maschine ausgibt — reproduzierbar, kommentiert, wiederverwendbar.

daten |>
  group_by(maschine) |>
  summarise(mittel = mean(masse_mm, na.rm = TRUE))
# → # A tibble: 3 × 2
#   maschine mittel
# 1 M1        10.0
# 2 M2         9.98
# 3 M3        10.1

Ein Aufruf, drei Zeilen, fertig. Bis dahin sind es neun Schritte — und du gehst sie in dieser Lektion selbst.

Schritt 1 — Taschenrechner vs. R

Ein Taschenrechner rechnet ein Ergebnis. R rechnet ein Verfahren — und das Verfahren ist das, was du abgibst.

TaschenrechnerR
WiederholenAlles neu eintippenSkript erneut laufen lassen
NachvollziehenWas hast du damals gedrückt?Jede Zeile steht in der Datei
Wachsen120 Werte: machbar — 120 000 nichtGleicher Code, jede Größe
TeilenNur das ErgebnisDer ganze Weg, prüfbar
Merksatz

Der Taschenrechner liefert dir ein Ergebnis. Ein R-Skript liefert dir den Weg — und nur der Weg lässt sich wiederholen, prüfen und begründen. Genau das verlangt die Matura.

Schritt 2 — R und RStudio sind zwei Dinge

Das ist die häufigste Verwechslung am Anfang: R und RStudio sind nicht dasselbe.

RRStudio
Was ist das?Die Sprache und die Rechen-EngineDie Oberfläche (IDE) zum Bedienen von R
Ohne das andere?Läuft auch im Terminal — nur mühsamLäuft nicht ohne R
AnalogDer MotorDas Cockpit

Deshalb gilt beim Installieren: zuerst R, dann RStudio. RStudio ist nur das Cockpit — gerechnet wird im Motor. Wer RStudio ohne R startet, sitzt in einem Cockpit ohne Motor.

Installation

R von cran.r-project.org, RStudio Desktop von posit.co/download/rstudio-desktop — in dieser Reihenfolge, einmal pro Rechner. Auf den Schul-Laptops steht die Schritt-für-Schritt-Anlage bei deiner Lehrperson bereit.

Schritt 3 — Die vier Fenster von RStudio

Wenn du ein Skript öffnest, teilt RStudio das Fenster in vier Bereiche. Jeder hat eine Aufgabe:

FensterAufgabe
Editor (oben links)Hier schreibst du dein Skript — die Datei, die bleibt.
Console (unten links)Hier rechnet R. Zeigt Ergebnisse und Fehler. Nichts hier ist dauerhaft.
Environment (oben rechts)Welche Objekte gerade existieren (Variablen, Daten).
Files / Plots (unten rechts)Dateien, Grafiken, Hilfe, Pakete.
Die eine Regel

Code steht im Skript (Editor), nicht in der Console. Die Console ist zur Kontrolle da — das Skript ist die Quelle der Wahrheit.

Schritt 4 — Ein Projektordner statt Dateichaos

Ein R-Projekt ist einfach ein Ordner, den R als Zuhause kennt. In diesem Ordner liegt eine Projektdatei .Rproj — ein Doppelklick darauf öffnet RStudio genau hier, mit dem richtigen Arbeitsverzeichnis.

pmm-km7-04/
├── pmm-km7-04.Rproj     ← Doppelklick öffnet das Projekt
├── data/
│   └── betriebsdaten.csv ← die Messwerte
├── scripts/
│   └── analyse.R         ← dein Skript
└── output/
    └── kennzahlen.csv    ← was R speichert

Das Arbeitsverzeichnis ist der Ordner, in dem R sucht und speichert. Du fragst es so ab:

getwd()
# → "…/pmm-km7-04"   (dein Projektordner)

Weil das Arbeitsverzeichnis das Projekt ist, schreibst du Pfade relativ dazu — ohne Laufwerksbuchstaben, mit Schrägstrich /:

# gut: relativ zum Projekt
daten <- read_csv("data/betriebsdaten.csv")

# schlecht: absolut, funktioniert nur auf deinem Rechner
daten <- read_csv("C:/Users/Anna/Downloads/betriebsdaten.csv")
Warum kein setwd()?

Mit setwd() müsstest du in jedem Skript den Pfad neu setzen — und auf einem anderen Rechner stimmt er nicht. Das Projekt macht das für dich: öffnen genügt.

Schritt 5 — Das erste Skript

Ein Skript ist eine Datei mit R-Befehlen, die du speicherst und immer wieder ausführst. Drei Dinge musst du kennen:

a) Anlegen. File → New File → R Script (oder Ctrl/Cmd + Shift + N) und unter einem sprechenden Namen speichern, z. B. scripts/analyse.R.

b) Ausführen. Cursor in die Zeile, Ctrl + Enter — die Zeile läuft in der Console. Mit Ctrl + Shift + S läuft das ganze Skript.

c) Schreiben. Zwei Zeichen tragen die ganze Logik: # für einen Kommentar (R ignoriert ihn) und <- für eine Zuweisung („Objekt bekommt Wert").

# analyse.R — Kennzahlen je Maschine
library(tidyverse)

# Messwerte einlesen (relativ zum Projekt)
daten <- read_csv("data/betriebsdaten.csv")

# Kennzahlen je Maschine berechnen
kennzahlen <- daten |>
  group_by(maschine) |>
  summarise(
    n      = sum(!is.na(masse_mm)),
    mittel = mean(masse_mm, na.rm = TRUE),
    s      = sd(masse_mm, na.rm = TRUE)
  )

kennzahlen
# → # A tibble: 3 × 4
#   maschine     n mittel      s
# 1 M1          37  10.0  0.0315
# 2 M2          39   9.98 0.0400
# 3 M3          40  10.1  0.0696

Lies die Ausgabe wie einen Satz: nimm die Daten → gruppiere nach Maschine → fasse zusammen. M2 liegt unter dem Sollmaß, M3 darüber — genau die Frage aus dem Einstieg.

Objektnamen

Namen dürfen Buchstaben, Ziffern, _ und . enthalten und beginnen mit einem Buchstaben. Konvention: snake_case, klein, mit Unterstrich — mittel_wert, nicht MittelWert. Groß- und Kleinschreibung zählt: daten und Daten sind zwei Objekte.

Schritt 6 — „Source" verwirft nichts

Nein — „Source" verwirft nichts. Es führt die Datei von oben nach unten in derselben Konsole aus, die Ausgabe hängt unten an, und alle Objekte im Environment bleiben. Was du willst („frisch anfangen"), ist ein anderer Befehl.

was es istwie es leer wird
Konsole Protokoll dessen, was gelaufen ist Ctrl + L (nur Anzeige, Zustand bleibt!)
Environment die Objekte im Speicher (daten, tab, urxn …) Restart R
Skript die Quelle der Wahrheit wird nie geleert

„Alte Konsole verworfen" ist deshalb das falsche Ziel: Die Konsolenausgabe ist egal, das Environment ist das Problem. Ein Objekt von vorhin kann einen Fehler verdecken — zum Beispiel läuft chisq.test(tab) weiter, obwohl die Zeile tab <- table(...) im Skript einen Tippfehler hat, weil tab noch von Hand in der Konsole entstanden ist.

Schritt 7 — Der Workflow: entwickeln, debuggen, kalt prüfen

Vier Schritte, und der letzte ist der, den man gern überspringt:

  1. Entwickeln — Ctrl + Enter — Zeile oder Auswahl ausführen (Konsole = Notizzettel).
  2. Debuggen — Ctrl + Alt + B — Anfang bis Cursor ausführen.
  3. Prüfen — Ctrl + Shift + F10 — Restart R (leeres Environment!).
  4. Dann — Ctrl + Shift + S — Source: den ganzen Skript kalt durchlaufen.

Schritt 3 und 4 sind der eigentliche Test: Das Skript muss aus einem leeren R heraus laufen. Wenn nach dem Restart could not find function "read_csv" kommt, fehlt library(tidyverse) — genau der Fehler, der beim zeilenweisen Arbeiten unsichtbar bleibt. Wenn es durchläuft und die Ausgabedatei neu schreibt, ist die Auswertung reproduzierbar. Das ist die Definition, die in dieser Lektion gilt: ein Skript, das in einem Jahr noch läuft.

Zwei Nebenwirkungen von Restart R, die man kennen muss: geladene Pakete sind weg (deshalb library() oben im Skript), und getwd() ist wieder die Projektwurzel.

Knopf im EditorKürzelWas passiert
RunCtrl + Enter aktuelle Zeile oder Auswahl
SourceCtrl + Shift + S ganze Datei, still — nur print und Ausgaben erscheinen
Source with Echo Ctrl + Shift + Enter ganze Datei, jede Zeile wird mitgezeigt — gut zum Vorführen
Source on SaveHäkchen beim Speichern läuft das Skript — beim Entwickeln lästig

Damit „kalt" auch stimmt, zwei Schalter: RStudio stellt den Speicher standardmäßig wieder her. Unter Tools → Global Options → General deshalb Restore .RData into workspace at startup auf No und Save workspace to .RData on exit auf Never. Oder pro Projekt in der .Rproj, dann gilt es für alle, die das Projekt öffnen:

RestoreWorkspace: No
SaveWorkspace: No
In einem Satz

Die Konsole ist ein Notizzettel, das Environment ist der Zustand, das Skript ist das Ergebnis — „Source" wiederholt das Ergebnis auf dem vorhandenen Zustand, „Restart R, dann Source" prüft, ob das Ergebnis auch allein steht.

Schritt 8 — Viewer und Presentation

Rechts unten sind es nicht vier Tabs, sondern sechs. Viewer und Presentation sind beide Browser-Fenster innerhalb von RStudio — der Unterschied ist, was sie anzeigen.

TabZeigt
Filesdein Projekt auf der Platte
Plotsstatische Grafiken aus dieser Sitzung
Packagesinstallierte Pakete, Install und Update
Help?funktion, Vignetten, ??suche
Viewererzeugten Web-Inhalt (Widgets, HTML-Vorschau, Shiny)
PresentationHTML-Foliendecks (reveal.js, .Rpres) im Vortragsmodus

Viewer — ein Browsertab, den RStudio für dich aufmacht

Der Viewer zeigt von R erzeugten Web-Inhalt: htmlwidgets wie plotly, leaflet oder DT-Tabellen erscheinen dort automatisch, HTML-Ausgaben von Quarto und R Markdown ebenfalls (umschaltbar unter Tools → Global Options → R Markdown → Show output preview in). Auch eine lokale HTML-Datei kannst du dort öffnen:

rstudioapi::viewer("lesson.html")
# oder im Files-Tab: Rechtsklick → View in Browser

Er hat Refresh, Zoom und „Show in new window" — aber keine Adresszeile.

Presentation — ein Folien-Player

Der Presentation-Tab blättert ein HTML-Foliendeck im Vollbild durch, eine Folie pro Bildschirm, mit Pfeiltasten und Leertaste. Gedacht ist er für Quartos revealjs-Format; historisch war es der Player für .Rpres (R Presentations) und für ioslides- und slidy-Decks. Das Tab erscheint erst, wenn ein solches Deck gerendert wird.

Deine lesson.html

Unsere Lektionen sind keine reveal.js-Decks, sondern handgebaute HTML-Seiten mit assets/lesson.css — der Presentation-Tab bleibt dafür leer. Zum Ansehen nimm den Viewer; für „genau wie auf GitHub Pages" den Live-Server (./serve.sh), weil Firefox lokale Dateien mit Verweisen in Elternordner blockt.

Schritt 9 — Pfade, die halten

Ein Pfad im Skript ist ein Versprechen über die Ordnerstruktur. Es hält nur, wenn es relativ formuliert ist:

absolut
/home/georg/…, C:/Users/…		relativ
daten/x.csv
funktioniertgenau einmal, auf einem Rechnerüberall, wo die Ordnerstruktur gleich ist
bricht beianderem Benutzer, anderem Laufwerk, Abgabefalschem Arbeitsverzeichnis
legitim beiEinmal-Exploration, file.choose(), tempdir(), Pfad aus einer Umgebungsvariableallem, was im Skript bleibt und geteilt wird

Feinheiten, die in der Praxis wirklich beißen:

  • ~ ist absolut in Verkleidung — ~ ist das Home des jeweiligen Benutzers.
  • Backslashes aus dem Windows-Explorer sind zu verdoppeln oder durch / zu ersetzen — R akzeptiert / auch unter Windows.
  • Daten, die zur Analyse gehören, liegen im Projekt und werden relativ angesprochen — nicht per ../ aus dem Projekt herausklettern.

Diagnose statt Raten:

getwd()                        # wo bin ich?
list.files("daten")            # was liegt dort?
file.exists("daten/betriebsdaten.csv")   # ist die Datei da?

# Daten ins Projekt holen statt nach außen zeigen:
dir.create("daten", showWarnings = FALSE)
file.copy("../../assets/betriebsdaten.csv", "daten/betriebsdaten.csv")

Die Fehlermeldung cannot open file nennt immer den aufgelösten Pfad — vergleiche ihn mit getwd(). Genau daran erkennt man den Unterschied zwischen „Datei fehlt" und „Arbeitsverzeichnis ist falsch".

Du bekommst cannot open file: 'daten/betriebsdaten.csv'. Was prüfst du zuerst?

Alles im Skript, Zeile für Zeile mit Ctrl + Enter:

  1. Projekt anlegen. File → New Project → New Directory → Empty Project, Name pmm-km7-04. Lege darin die Ordner data/ und scripts/ an und kopiere betriebsdaten.csv nach data/.
  2. Vorhersage zuerst. Öffne ein neues Skript scripts/analyse.R. Schreib vor der Ausführung auf: Welche der drei Maschinen hat den größten Mittelwert — und welche den kleinsten? Führe dann den Code aus Schritt 5 aus.
  3. Prüfen. Gib getwd() aus. Endet die Ausgabe auf pmm-km7-04? Wenn nicht: Ist das Projekt geöffnet (Doppelklick auf die .Rproj-Datei)?
  4. Kaltstart. Ctrl + Shift + F10, dann Ctrl + Shift + S. Läuft das Skript aus einem leeren R durch, ohne dass du vorher etwas in der Konsole getippt hast? Was fehlt, fehlt im Skript.
Typische Fehler

Fehler 1 — Code in der Console statt im Skript

2 + 2
# ✗ Ergebnis 4 — aber nach dem Schließen ist alles weg

Was du in der Console tippst, ist nach der Sitzung verloren. Alles, was zählt, gehört ins Skript und wird gespeichert.

Fehler 2 — Das Projekt ist nicht geöffnet

read_csv("data/betriebsdaten.csv")
# ✗ Error: 'data/betriebsdaten.csv' does not exist

Die Datei liegt richtig — nur das Arbeitsverzeichnis ist ein anderes, weil RStudio ohne Projekt gestartet wurde. getwd() zeigt es. Lösung: Projekt öffnen, nicht RStudio „nackt".

Fehler 3 — Absolute Pfade

read_csv("C:\\Users\\Anna\\Downloads\\betriebsdaten.csv")

Läuft auf Annas Rechner — und nirgendwo sonst. Im Skript immer relativ, mit /. Wer das Skript weitergibt, will, dass es auch dort läuft.

Fehler 4 — Skript geändert, aber nicht gespeichert

# ✗ oben steht neuer Code, ausgeführt wird die alte gespeicherte Fassung

Ctrl + Shift + S führt die gespeicherte Datei aus. Wenn es sich falsch anfühlt: Tabulator zeigt einen Stern / Punkt am Dateinamen — dann fehlt Ctrl + S.
