Einstiegsfrage

Von der letzten Lektion kennst du die Pinguine. Jetzt wird es betrieblich: Wie schwer ist eine „typische“ Pinguin-Art — und unterscheidet sich das nach Geschlecht?

Mit Plots allein antwortet man darauf vage („irgendwie schwerer“). Mit dplyr antwortest du mit einer Zahl — und Zahlen kann man gegen Toleranzen und Grenzwerte prüfen. Das ist Qualitätsarbeit.

In der zweiten Beispielwelle stellen wir dieselbe Frage schärfer: Welche Art auf welcher Insel wiegt im Schnitt am meisten — und wie streut das Gewicht? Auch darauf gibt dir dplyr eine Tabelle als Antwort.

Ziel-Artefakt

Diese Pipe beantwortet die Einstiegsfrage:

penguins |>
  filter(sex == "female") |>
  group_by(species) |>
  summarise(gewicht_g = mean(body_mass_g, na.rm = TRUE))
speciesgewicht_g
Adelie3369
Chinstrap3527
Gentoo4680

Drei Verben, drei Zeilen Ausgabe, eine saubere Antwort. Der Win von heute: Du liest diese Pipe vor dir her und weißt ohne Ausführen, was sie tut.

Schritt 1 — Die Pipe: lesen wie einen Satz

Die Pipe |> (Rohrleitung) reicht das Ergebnis links als erstes Argument an die Funktion rechts weiter. So liest sich eine Kette wie ein Rezept statt wie eine Verschachtelung:

# Ohne Pipe — von innen nach außen, rückwärts denken
summarise(
  filter(penguins, species == "Gentoo"),
  gram = mean(body_mass_g, na.rm = TRUE)
)

# Mit Pipe — von oben nach unten, wie ein Rezept
penguins |>
  filter(species == "Gentoo") |>
  summarise(gram = mean(body_mass_g, na.rm = TRUE))
#> 1 Zeile: gram = 5076 — der Gentoo-Mittelwert

Ohne Pipe dachtest du rückwärts: was ganz außen steht, läuft zuerst. Mit der Pipe liest man von oben nach unten — Schritt für Schritt, so wie die Auswertung wirklich abläuft. Jedes dplyr-Verb nimmt eine Tabelle an und gibt eine Tabelle zurück; deshalb lassen sich die Verben an die Pipe hängen wie Waggons an eine Lokomotive.

Schritt 2 — Die fünf dplyr-Verben

dplyr ist eine kleine Grammatik mit genau fünf Verben. Alles, was du heute baust, besteht aus Kombinationen dieser fünf:

VerbMachtVorsicht
filter()Zeilen nach Bedingung behaltenVerwechslungs-Klassiker mit select
select()Spalten auswählenderselbe Klassiker
mutate()neue Spalte berechnenüberschreibt gleichnamige Spalten
arrange()Zeilen sortierendesc() für absteigend
summarise()zu einer Zeile zusammenfassenna.rm = TRUE!

Ein Verb pro Pipe-Schritt — so bleibt jede Zeile Code ein Gedanke. Die Verben hängen alle an der Pipe aus Schritt 1.

Schritt 3 — filter() & select(): Zeilen und Spalten

filter() behält, was die Bedingung erfüllt. Mehrere Bedingungen trennst du mit Komma — das heißt UND:

# Zeilen: nur Gentoo (Vergleich ==, nicht =)
penguins |> filter(species == "Gentoo")
#> 124 Zeilen — alle Gentoo-Pinguine

# Zeilen: Gentoo UND schwerer als 5 kg (Komma = und)
penguins |> filter(species == "Gentoo", body_mass_g > 5000)
#> 61 Zeilen

# Zeilen: Flügellänge über 210 mm
penguins |> filter(flipper_length_mm > 210)
#> 100 Zeilen

Achte auf die Zeichen: Vergleichen macht == (ist gleich), zuweisen macht <-. Ein einzelnes = ist hier ein Fehler — mehr dazu in den typischen Fehlern.

Und select() wählt Spalten statt Zeilen — es schneidet die Tabelle so zu, dass nur übrig bleibt, was die Auswertung braucht:

penguins |> select(species, island, body_mass_g)
#> alle 344 Zeilen, aber nur 3 Spalten
Der Klassiker

filter = Zeilen (behalten/weglassen) · select = Spalten (auswählen/abwählen). Die beiden Verben zu vertauschen ist der häufigste Fehler in dieser Lektion.

Schritt 4 — mutate() & arrange(): rechnen und ordnen

mutate() (umformen) rechnet Spalte für Spalte: aus Gramm Kilogramm, aus Millimeter Zoll, aus zwei Werten eine Differenz. Bestehende Spalten bleiben unangetastet — die neue kommt ganz rechts dazu:

# Gramm → Kilogramm: neue Spalte, Einheiten sauber
penguins |>
  mutate(kg = body_mass_g / 1000) |>
  select(species, kg) |>
  head(3)
#> Adelie  3.75   Adelie  3.80   Adelie  3.25

Wichtig für die Praxis: Rechenregeln gehören in eine Spalte mit Klartext-Namen (kg, sd_g) — nicht in den Kopf, wo die Regel drei Wochen später verloren ist. Bestehende Spalten werden nur überschrieben, wenn du denselben Namen wiederverwendest.

arrange() sortiert die Zeilen — aufsteigend von selbst, mit desc() (absteigend) kommt das Größte zuerst. Fehlende Werte setzt R dabei standardmäßig ans Ende: sortiert wird über die echten Zahlen hinweg, die NA-Zeilen rutschen nach hinten.

# Sortieren: die schwersten zuerst
penguins |>
  select(species, body_mass_g) |>
  arrange(desc(body_mass_g)) |>
  head(3)
#> Gentoo 6300   Gentoo 6050   Gentoo 6000

Schritt 5 — group_by() + summarise(): die Antwort-Maschine

summarise() (zusammenfassen) macht aus vielen Zeilen eine: Mittelwert, Minimum, Anzahl. Mit group_by() davor geschieht das pro Gruppe — eine Gruppe = eine Zeile:

penguins |>
  group_by(species) |>
  summarise(
    n    = n(),
    gram = mean(body_mass_g, na.rm = TRUE),
    sd_g = sd(body_mass_g, na.rm = TRUE)
  )
speciesngramsd_g
Adelie1523701459
Chinstrap683733384
Gentoo1245076504

Die drei Bausteine der Tabelle: n() zählt die Zeilen der Gruppe, mean() fasst das Gewicht zum Durchschnitt zusammen, sd() misst die Streuung (Standardabweichung) — also, wie weit die Einzelgewichte typischerweise vom Mittelwert streuen. Genau das war das Ziel-Artefakt, nur ohne den filter auf Weibchen.

Gruppen können noch feiner sein — nach Art und Insel:

penguins |>
  group_by(species, island) |>
  summarise(
    n    = n(),
    gram = mean(body_mass_g, na.rm = TRUE),
    sd_g = sd(body_mass_g, na.rm = TRUE),
    .groups = "drop"
  )
speciesislandngramsd_g
AdelieBiscoe443710488
AdelieDream563688455
AdelieTorgersen523706445
ChinstrapDream683733384
GentooBiscoe1245076504

Gentoo auf Biscoe: 5,1 kg — Kopf und Schulter über allen anderen Gruppen. Die Inseln sind übrigens unterschiedlich besetzt: 168 Pinguine sitzen auf Biscoe, 124 auf Dream, 52 auf Torgersen. Das kannst du mit einer Kurzform der Antwort-Maschine selbst prüfen — count(island) zählt die Zeilen je Insel:

penguins |> count(island)
#> Biscoe 168 · Dream 124 · Torgersen 52
Antwort auf die Einstiegsfrage

Adelie-Weibchen wiegen im Mittel 3369 g, Chinstrap-Weibchen 3527 g, Gentoo-Weibchen 4680 g — Gentoo-Weibchen sind rund 1,3 kg schwerer als Adelie-Weibchen.

Zwei Feinheiten an der Antwort-Maschine, auf die du achten solltest:

Erstens: Achte auf Adelie/Torgersen — n zeigt 52, aber der Mittelwert rechnet über nur 51 Werte. n() zählt alle Zeilen der Gruppe; mean(..., na.rm = TRUE) ignoriert zusätzlich die Zeile mit fehlendem Gewicht. Genau dieser Unterschied führt uns zum Thema des nächsten Schritts: fehlende Werte.

Zweitens: Der Hinweis „summarise() has regrouped the output“, den R bei mehrstufiger Gruppierung meldet, heißt: die Gruppierung bleibt nach dem Zusammenfassen teilweise bestehen (hier: nach species). Mit .groups = "drop" gibst du die Gruppierung vollständig frei und bekommst eine ganz gewöhnliche Tabelle zurück.

In der Art×Insel-Tabelle zeigt Adelie/Torgersen n = 52, aber der Mittelwert rechnet über nur 51 Werte. Warum?

Schritt 6 — NA: fehlende Messwerte verstehen

NA (Not Available) ist nicht Null und nicht leer — es ist ein eigener Zustand: „hier fehlt ein Wert“. Warum das wichtig ist, zeigt ein Mini-Vektor:

x <- c(3750, 3800, NA, 3250)

mean(x)
#> NA — ansteckend!

mean(x, na.rm = TRUE)
#> 3600 — NA aus der Rechnung entfernt

is.na(x)
#> FALSE FALSE TRUE FALSE

is.na() prüft Wert für Wert, ob etwas fehlt — praktisch, wenn du zählen willst, wo die Lücken sind. Die Pinguin-Tabelle hat echte Lücken: 2 Pinguine fehlen bei den Längen- und Gewichts- messungen, 11 Pinguine haben kein eingetragenes Geschlecht.

Wichtig

NA steckt jede Rechnung an: ein einziger fehlender Wert macht das gesamte mean()-Ergebnis zu NA. Deshalb steht in der Antwort-Maschine überall na.rm = TRUE. Aber frag zuerst, warum ein Wert fehlt — bevor du ihn wegrechnest.

Diese Frage ist nicht Akademie. Bei den Pinguinen fehlen die Werte bei echten Messproblemen (ein Pinguin, der in der Falle nicht vermessen wurde, hat schlicht kein Gewicht). In Betriebsdaten kann ein fehlender Wert aber auch heißen: Messung vergessen, Sensor ausgefallen, Nachmessen verweigert. Die Ursache entscheidet, ob na.rm = TRUE ehrlich ist — oder ob du damit gerade den Defekt unsichtbar machst.

Schritt 7 — Code-Stil: lesbar ist wartbar (Kap. 4)

Zwei Pipes können rechnerisch dasselbe tun und trotzdem grundverschieden lesbar sein. So sieht guter Stil aus:

# Guter Stil: snake_case, Leerzeichen, kurze Zeilen
body_mass_kg <- penguins |>   # Pipe am ZEILENENDE
  filter(species == "Gentoo") |>
  mutate(kg = body_mass_g / 1000)
RegelWarum
Namen: snake_casekeine Rätsel über Groß-/Kleinschreibung
Leerzeichen um Operatorenkg = g / 1000 statt kg=g/1000
|> ans Zeilenendeggplot-+-Regel — gleiche Logik

Stil ist kein Ästhetik-Thema: Du liest deinen Code in drei Wochen wieder — schreibe für dieses Du. Dieselbe Regel kennst du schon aus SA-01: dort steht das + der ggplot-Kette am Zeilenende, hier die Pipe. Ein Gedanke, zwei Werkzeuge.

Schritt 8 — Skripte & Projekte (Kap. 6)

Ab heute arbeitest du in einem RStudio-Projekt — einem eigenen Verzeichnis pro Auswertung. Dann stimmen alle Pfade von selbst:

pmm-ue02/            # ein Ordner = ein Projekt
  pmm-ue02.Rproj     # File → New Project → New Directory
  analyse.R          # dein Skript
  messwerte.csv      # Daten liegen daneben
Faustregel

Projekt-Ordner = Wurzel. Relative Pfade ("messwerte.csv") statt absoluter ("C:/Users/…"). Dann läuft dein Skript auch auf dem Rechner der Kollegin.

Warum das wichtig wird: Bis jetzt kamen die Pinguine per data() mit dem Paket — sie leben im R. Echte Betriebsdaten liegen als Datei auf der Festplatte, und genau da entscheidet der Pfad, ob dein Skript läuft. In der nächsten Lektion liest du echte CSV-Dateien ein — relative Pfade werden dann zum Alltag.

Vier Behauptungen über select() — welche davon stimmt wirklich?
Jetzt du!

Vor jeder Ausführung gilt das Ritual: erst vorhersagen, hinschreiben, dann ausführen. Schreibe die Pipes in dein Skript aus Schritt 8.

  1. Vorhersage zuerst: Was liefert penguins |> filter(species == "Adelie") |> nrow()? Und was passiert, wenn du select statt filter schreibst? Notiere beide Vorhersagen, dann ausführen.
  2. Ausführen: Wie viele Pinguine wiegen mehr als 4,5 kg? (Pipe: filter(body_mass_g > 4500) + nrow().) Zeige danach die drei schwersten mit select() und arrange(desc(body_mass_g)).
  3. Übertrag: Baue die Ziel-Pipe um auf Männchen (sex == "male") und gebe das Gewicht in Kilogramm aus — via mutate(), Spaltenname gewicht_kg, gerundet auf eine Nachkommastelle.
  4. Vorhersage zum Schluss: Was passiert mit der Ausgabe der Ziel-Pipe, wenn du na.rm = TRUE weglässt? Notiere deine Vorhersage — dann prüfen.
Typische Fehler

1. = statt == im filter

penguins |> filter(species = "Gentoo")
# ✗ „We detected a named input. This usually means that you've
#    used = instead of ==. Did you mean species == "Gentoo"?“
Merke

= übergibt, == vergleicht. Im filter vergleichtest du — also ==. Zuweisen macht <-.

2. na.rm vergessen — eine Zahl raus, aber die falsche: NA

penguins |> summarise(gram = mean(body_mass_g))
#> NA — und R warnt NICHT. mean() gibt schlicht NA zurück.

Das ist der laute-freie Fehler: keine Meldung, nur NA. Erklärung kennst du aus Schritt 6 — ein fehlender Wert steckt die Rechnung an. Regel: bei mean(), sd() und Kollegen in summarise() immer mitdenken, ob fehlende Werte vorhanden sein können.

3. group_by() vor ggplot() — die Gruppierung versinkt still

penguins |> group_by(species) |> ggplot(aes(x = body_mass_g)) +
  geom_histogram()
# → EIN Histogramm, als gäbe es keine Gruppen

Du erwartest drei kleine Histogramme — eins pro Art — und bekommst ein Histogramm über alle 344 Pinguine. Der Grund: ggplot liest die dplyr-Gruppierung nicht aus dem Datensatz; die Gruppe muss in die Zeichnung hinein — aes(fill = species) (Histogramme übereinander) oder + facet_wrap(~species) (drei Panels). Und für die Antwort-Tabelle gehört nach group_by() ohnehin ein summarise().

4. Filter-Ergebnis gespeichert — geglaubt

penguins |> filter(species == "Gentoo")
# → zeigt 124 Zeilen an, aber penguins ist UNVERÄNDERT

Ohne Zuweisung (gentoo <- …) verändert dplyr nichts — das Ergebnis verpufft im Bildschirm. dplyr arbeitet unveränderlich: gut so, aber merken.
