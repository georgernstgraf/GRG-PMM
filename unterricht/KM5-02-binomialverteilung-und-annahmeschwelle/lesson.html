Die Annahmeschwelle: wie viele Teile darf ich prüfen?

Binomialverteilung, Akzeptwahrscheinlichkeit — und warum ein Stichprobenplan nie beide Seiten gewinnen kann.

Lektüre

Navarro, Statistik für Human- und Sozialwissenschaftler (deutsch) — Kap. 9 (Probability). Wenn du das Wege zählen (n über k, Pascalsches Dreieck) noch nicht sitzen hast: Lektion KM5-01 — die Lektion setzt genau dort an.

Einstiegsfrage

Maschine M3 hat 6 von 40 Teilen außerhalb der Toleranz geliefert. Alle anderen Maschinen: keine.

Sind die 6 Teile ein Signal — oder völlig normal?

Die Antwort braucht keine Vermutung, sondern eine Verteilung. Heute bauen wir sie: die Binomialverteilung — das Werkzeug hinter jeder Annahmestichprobenprüfung und hinter dem Chi-Test, den wir als Nächstes machen.

Ziel-Artefakt

Der eine Aufruf, der am Ende alles leistet:

pbinom(c, size = n, prob = p)
# → „Mit welcher Wahrscheinlichkeit komme ich mit
#     höchstens c Fehlern durch, wenn ich n Teile prüfe
#     und die Fehlerquote p ist?"

Ein Aufruf, drei Zahlen — und daraus die Entscheidung, ob ein Los angenommen oder zurückgewiesen wird.

Schritt 1 — Das Zufallsexperiment

Die Binomialverteilung beschreibt genau zwei Dinge:

  1. Jedes Teil ist entweder i.O. oder i.O. — ein Ja/Nein-Ergebnis, nichts dazwischen.
  2. Jedes Teil hat dieselbe Wahrscheinlichkeit p.

Meßgrößen wie „10,02 mm" sind dafür zu fein. Aber „in Toleranz / außerhalb" ist genau diese Ja/Nein-Frage. Und „6 von 40" ist genau diese Zählung.

Zwei Parameter bestimmen alles: die Stückzahl n und die Fehlerquote p. Der Erwartungswert ist die Quintessenz:

E(X) = n * p
# bei n = 40 und p = 0,10:  E(X) = 4 defekte Teile
Anschluss an KM5-01

Die Binomialverteilung ist genau die Verteilung, für die du in KM5-01 das Pascalsche Dreieck gebaut hast. Jetzt kommt die zweite Stufe: die Gewichtung. choose(5, 2) zählt die Wege, dbinom(2, 5, 0.1) gewichtet sie.

Schritt 2 — dbinom: genau k Treffer

5 Teile werden geprüft, die Fehlerquote beträgt 10 %. Wie wahrscheinlich ist genau 2 davon defekt?

dbinom(0:5, size = 5, prob = 0.1)
# → 0.59049 0.32805 0.07290 0.00810 0.00045 0.00001
#     ↑        ↑        ↑        ↑        ↑        ↑
#     0        1        2        3        4        5 Fehler

Lies die Zahlen von links: 0 Fehler ist mit 59 % am wahrscheinlichsten, 1 Fehler mit 33 %. Zusammen sind das 92 % — ein „sauberes" Los ist der Normalfall. Zwei oder mehr Fehler passieren nur in 8,1 % aller Fälle:

pbinom(1, size = 5, prob = 0.1, lower.tail = FALSE)
# → 0.08146
Die vier d/p/q/r-Funktionen

Eine Verteilung hat immer vier Ansichten — und die Buchstaben merken sich nach ihrer Frage:

FunktionFragt
dbinom(k, n, p)Wie wahrscheinlich sind genau k?
pbinom(k, n, p)Wie wahrscheinlich sind höchstens k?
qbinom(q, n, p)Welcher k-Wert gehört zur Quantile q?
rbinom(N, n, p)Erzeuge N Zufallszüge

Für die Annahmestichprobe brauchst du fast nur pbinom.

Du prüfst 10 Teile und nimmst die Charge an, wenn höchstens 1 Teil defekt ist. Welcher Aufruf berechnet die Akzeptwahrscheinlichkeit bei einer Fehlerquote von 5 %?

Schritt 3 — Die Akzeptwahrscheinlichkeit

Jetzt der eigentliche Zweck. Ein Stichprobenplan besteht aus genau zwei Zahlen:

n = 10   Stichprobenumfang:  so viele Teile prüfen wir
c = 1    Annahmeschwelle:  so viele Fehler dulden wir noch

Die Regel lautet: höchstens c Fehler → annehmen, mehr → zurückweisen. Und pbinom(c, n, p) sagt uns, wie oft das bei einer wahren Fehlerquote p passiert. Das ist die OC-Kurve (Operating-Characteristic-Kurve) in Tabellenform:

pfehler <- c(0.05, 0.10, 0.15, 0.20)

sapply(0:2, function(c) round(pbinom(c, 10, pfehler), 4))
# →       c=0     c=1     c=2
#   p=0.05  0.5987  0.9139  0.9885
#   p=0.10  0.3487  0.7361  0.9298
#   p=0.15  0.1969  0.5443  0.8202
#   p=0.20  0.1074  0.3758  0.6778

Jede Zelle ist eine Akzeptwahrscheinlichkeit. Lies zwei Punkte daraus:

  • Links oben (p = 0,05, c = 1): 91,4 % — ein guter Prozess kommt fast immer durch. Das ist das Produzentenrisiko: gute Lose werden zu oft zurückgewiesen.
  • Rechts unten (p = 0,20, c = 1): 37,6 % — aber 62,4 % der schlechten Lose kommen trotzdem durch! Das ist das Warenrisiko (Konsumentenrisiko): Der Kunde bekommt Ausschuss geliefert.
Der Kern der ganzen Lektion

Hebst du c von 1 auf 2, verbessert sich die linke Spalte (0,914 → 0,989) — aber die rechte verschlechtert sich (0,544 → 0,820). Bei n = 10 gibt es keine Wahl, die beide Seiten gut aussehen lässt. Ein Stichprobenplan verteilt immer nur ein festes Risiko.

Bei n = 10 und c = 1 gilt: P(annehmen | p = 0,05) = 0,9139 und P(annehmen | p = 0,15) = 0,5443. Was bedeutet die 0,5443 im Klartext?

Schritt 4 — Die Annahmeschwelle rückwärts rechnen

Meist ist die Aufgabe umgekehrt: Der Kunde gibt die Qualitätsvorgabe vor, und du suchst den Stichprobenumfang.

„Unser Prozess hat 5 % Ausschuss. Wir wollen, dass ein gutes Los
 mit mindestens 95 % Wahrscheinlichkeit durchkommt.
 Wie viele Teile müssen wir prüfen, wenn 2 Fehler erlaubt sind?"

Gesucht ist also das kleinste n mit pbinom(2, n, 0.05) ≥ 0,95. Rate einmal — dann rechne:

sapply(10:20, function(n) pbinom(2, n, 0.05))
# → n=10: 0.9885   n=13: 0.9755   n=16: 0.9571
#     n=11: 0.9848   n=14: 0.9699   n=17: 0.9497
#     n=12: 0.9804   n=15: 0.9638   n=18: 0.9419
#                                  ↑ hier kippt es

Die Antwort ist n = 15 oder 16 — bei n = 17 ist die Vorgabe von 95 % bereits gerissen. Merke die Richtung: größeres n macht die Akzeptwahrscheinlichkeit kleiner, weil im Mittel mehr Fehler auftauchen. Mehr prüfen ist nicht automatisch „sicherer".

Was kostet eine bessere Trennung?

Man braucht ein größeres n — aber nicht bei gleicher Schwelle. Der Vergleich, der zeigt warum:

plan <- data.frame(
  n         = c(10, 25, 25),
  c         = c( 1,  1,  3),
  gut       = round(pbinom(c(1, 1, 3), c(10, 25, 25), 0.05), 4),
  schlecht  = round(pbinom(c(1, 1, 3), c(10, 25, 25), 0.15), 4)
)
plan$trennung <- round(plan$gut - plan$schlecht, 4)
plan
# →    n  c    gut  schlecht  trennung
#     1 10  1  0.9139    0.5443     0.3696
#     2 25  1  0.6424    0.0931     0.5493
#     3 25  3  0.9659    0.4711     0.4948

Zeile 1 gegen Zeile 2: höheres n bei gleicher Schwelle c = 1 zerstört den Plan. Der gute Prozess kommt nur noch zu 64 % durch — man weist massenhaft gute Lose zurück. Zeile 2 gegen Zeile 3: Erst wenn man beides anhebt — n auf 25 und c auf 3 — bekommt man die Trennung zurück: 96,6 % der guten Lose durch, aber nur 47,1 % der schlechten.

Die Abwägung des Wareneingangs

Zeile 3 trennt besser als Zeile 1 (0,4948 gegen 0,3696) — und kostet dafür 2,5-mal so viele geprüfte Teile. Das ist keine Rechenaufgabe, sondern eine Entscheidung: Wie viel Prüfaufwand ist dir ein Prozentpunkte weniger Warenrisiko wert? Diese Frage wird in jedem Audit gestellt — und sie ist der Grund, warum Stichprobenpläne in Normen stehen.

Schritt 5 — Zurück zur Einstiegsfrage

Jetzt die 6 Ausschusteile von M3. Wenn die wahre Fehlerquote 10 % wäre, wäre die Akzeptwahrscheinlichkeit bei n = 40 und c = 6:

pbinom(6, size = 40, prob = 0.10)
# → 0.9005

Und die Wahrscheinlichkeit, genau 6 zu sehen:

dbinom(6, size = 40, prob = 0.10)
# → 0.10676

Bei 10 % Ausschuss sind im Mittel 4 defekte Teile zu erwarten, die Standardabweichung ist sqrt(40 * 0.1 * 0.9) = 1,90. Die 6 Teile liegen also rund 1,05 Standardabweichungen über dem Erwartungswert.

Die Antwort auf die Einstiegsfrage

6 von 40 sind bei einer 10-%-Quote ein völlig normales Ergebnis. Wer daraus auf ein Problem schließt, hat die Verteilung nicht gefragt. Ob M3 wirklich schlechter ist als 10 %, klärt erst ein Test — und genau den rechnen wir in KM7-02.

Jetzt du!

Alles im Skript:

  1. Vorhersage zuerst. Wie viel wahrscheinlicher ist 1 Fehler als 2 Fehler bei n = 5, p = 0,1? Rechne beides mit dbinom() und vergleiche deine Vermutung.
  2. Baue die OC-Tabelle für n = 20 über c = 0 bis 3. Vergleiche sie Zeile für Zeile mit der Tabelle für n = 10. Wo ist der Unterschied am größten — und warum gerade dort?
  3. Ein Kunde verlangt: „Ausschuss 5 %, Akzeptwahrscheinlichkeit mindestens 99 %, höchstens 1 Fehler erlaubt." Löse das nach pbinom() auf. Wie groß muss n mindestens sein? Und was passiert mit dem Warenrisiko bei p = 0,15?
Typische Fehler

Fehler 1 — dbinom statt pbinom

dbinom(1, 10, 0.05)     # → 0.3151 — nur „genau 1 Fehler"
pbinom(1, 10, 0.05)     # → 0.9139 — „0 oder 1 Fehler"

Die Akzeptannahme lautet „höchstens c" — das sind c + 1 Möglichkeiten, nicht eine. Wer dbinom(c, …) nimmt, vergisst den 0-Fehler-Fall und überschätzt die Zahl der abgelehnten Lose massiv.

Fehler 2 — lower.tail = FALSE vergessen

pbinom(1, 5, 0.1)                      # → 0.9185 (höchstens 1)
pbinom(1, 5, 0.1, lower.tail = FALSE)  # → 0.0815 (mindestens 2)

pbinom zählt standardmäßig von unten. „Wie viele Fehler mindestens?" verlangt das Umdrehen. Tipp: pbinom(k, n, p, lower.tail = FALSE) liest sich besser als 1 - pbinom(k - 1, n, p) — keine Rundungsfehler.

Fehler 3 — „Mehr prüfen macht das Risiko kleiner"

Für die Akzeptwahrscheinlichkeit ist es umgekehrt: n = 10 → 0,9885, n = 15 → 0,9638, n = 20 → 0,9245 bei c = 2. Mehr geprüfte Teile bedeuten im Mittel mehr gefundene Fehler, und die feste Schwelle c wird dadurch schneller überschritten. Mehr Prüfung kostet Risiko, sie baut es nicht ab.

Fehler 4 — Kontinuitägliches Merkmal in die Binomialverteilung

„6 von 40 außerhalb der Toleranz" funktioniert, weil jedes Teil nur zwei Zustände hat. „Wie viele Teile sind zwischen 9,98 und 10,02 mm?" funktioniert so nicht — das ist eine Normalverteilung mit pnorm(). Wähle die Verteilung nach der Frage, nicht nach der Gewohnheit.
