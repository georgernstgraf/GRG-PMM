Die Annahmeschwelle

Wie viele Teile darf ich prüfen —
und warum kein Stichprobenplan beide Seiten gewinnen kann.

5AHWIT · vor UE 1 (DoE) · 1. Doppelstunde
Lektüre

Navarro, Statistik für Human- und Sozialwissenschaftler (deutsch) — Kap. 9, Probability (Pflicht).

Fehlt dir das Wege zählen (n über k)? Dann zuerst Lektion KM5-01 — die heutige Lektion setzt dort an.

Einstiegsfrage

Maschine M3 hat 6 von 40 Teilen außerhalb der Toleranz.
M1 und M2: keine.

Sind die 6 Teile ein Signal — oder völlig normal?

Die Antwort braucht keine Vermutung, sondern eine Verteilung. Heute bauen wir sie.

Das Ziel: ein Aufruf, drei Zahlen

pbinom(c, size = n, prob = p)

# → "Mit welcher Wahrscheinlichkeit komme ich mit
#     höchstens c Fehlern durch, wenn ich n Teile prüfe?"

Daraus wird die Entscheidung: annehmen oder zurückweisen. Das ist jede Annahmestichprobe — und die Grundlage des Chi-Tests.

Zwei Bedingungen — mehr nicht

  1. Jedes Teil ist entweder i.O. oder i.O. — ein Ja/Nein-Ergebnis, nichts dazwischen.
  2. Jedes Teil hat dieselbe Wahrscheinlichkeit p.

„10,02 mm" ist dafür zu fein. Aber „in Toleranz / außerhalb" ist genau diese Ja/Nein-Frage.

E(X) = n * p

# n = 40, p = 0.10  →  E(X) = 4 defekte Teile
Anschluss an KM5-01

choose(5, 2) zählt die Wege — dbinom(2, 5, 0.1) gewichtet sie. Heute kommt die zweite Stufe.

dbinom: genau k Treffer

5 Teile, 10 % Fehlerquote. Wahrscheinlichkeit für genau 2 defekt?

dbinom(0:5, size = 5, prob = 0.1)

# → 0.59049 0.32805 0.07290 0.00810 0.00045 0.00001
#     ↑        ↑        ↑        ↑        ↑        ↑
#     0        1        2        3        4        5 Fehler

0 Fehler: 59 %. 1 Fehler: 33 %. Zusammen 92 % — ein sauberes Los ist der Normalfall.

Zwei oder mehr Fehler passieren nur in 8,1 %:

pbinom(1, size = 5, prob = 0.1, lower.tail = FALSE)
# → 0.08146

Vier Funktionen, vier Fragen

FunktionFragt
dbinom(k, n, p)Wie wahrscheinlich sind genau k?
pbinom(k, n, p)Wie wahrscheinlich sind höchstens k?
qbinom(q, n, p)Welcher k-Wert gehört zur Quantile q?
rbinom(N, n, p)Erzeuge N Zufallszüge

Für die Annahmestichprobe brauchst du fast nur pbinom.

Ein Stichprobenplan hat genau zwei Zahlen

n = 10   Stichprobenumfang:  so viele Teile pruefen wir
c = 1    Annahmeschwelle:  so viele Fehler dulden wir noch

Regel: höchstens c Fehler → annehmen, mehr → zurückweisen.

pbinom(c, n, p) sagt, wie oft das bei wahren Fehlerquote p passiert. Das ist die OC-Kurve in Tabellenform.

Die OC-Tabelle — das Herz der Lektion

pfehler <- c(0.05, 0.10, 0.15, 0.20)
sapply(0:2, function(c) round(pbinom(c, 10, pfehler), 4))
cp = 0,05p = 0,10p = 0,15p = 0,20
00,59870,34870,19690,1074
10,91390,73610,54430,3758
20,98850,92980,82020,6778

Links oben (0,9139): 91 % der guten Lose kommen durch. Das ist das Produzentenrisiko — gute Lose werden zu oft zurückgewiesen.

Rechts (0,5443): Aber 54 % der schlechten Lose kommen trotzdem durch! Das ist das Warenrisiko — der Kunde bekommt Ausschuss geliefert.

Der Kern: der Handel

Hebt du c von 1 auf 2, verbessert sich die gute Seite (0,914 → 0,989) — aber die schlechte verschlechtert sich (0,544 → 0,820).

Bei n = 10 gibt es keine Wahl, die beide Seiten gut aussehen lässt.

Ein Stichprobenplan verteilt immer nur ein festes Risiko.

Was kostet eine bessere Trennung?

n        = c(10, 25, 25)
c        = c( 1,  1,  3)
gut      = round(pbinom(c, n, 0.05), 4)
schlecht = round(pbinom(c, n, 0.15), 4)
rbind(n, c, gut, schlecht, trennung = round(gut - schlecht, 4))
ncgutschlechtTrennung
1010,91390,54430,3696
2510,64240,09310,5493
2530,96590,47110,4948

Zeile 1 → 2: n rauf bei gleicher Schwelle zerstört den Plan — der gute Prozess kommt nur noch zu 64 % durch.

Zeile 2 → 3: Erst wenn man beides anhebt, kommt die Trennung zurück — 96,6 % gut, 47,1 % schlecht. Preis: 2,5-mal so viele geprüfte Teile.

Rückwärts: wie viele darf ich prüfen?

Kundenvorgabe: „Ausschuss 10 %, Akzeptwahrscheinlichkeit mindestens 95 %, höchstens 2 Fehler." Gesucht ist das letzte n, bei dem die Garantie hält:

sapply(1:12, function(n) round(pbinom(2, n, 0.10), 4))

# n= 1: 1.0000   n= 5: 0.9914   n= 9: 0.9470  ← < 0.95
# n= 2: 1.0000   n= 6: 0.9842   n=10: 0.9104
# n= 3: 0.9990   n= 7: 0.9743   n=11: 0.8891
# n= 4: 0.9963   n= 8: 0.9619  ← letztes n mit ≥ 0.95

Antwort: n = 8 (0,9619). Größeres n macht die Akzeptwahrscheinlichkeit kleiner — im Mittel tauchen mehr Fehler auf.

Mehr prüfen ist nicht automatisch sicherer. Es kostet Risiko.

Zurück zur Einstiegsfrage

6 Ausschusteile bei M3. Wäre die wahre Quote 10 %, wie wahrscheinlich ist das dann?

dbinom(6, size = 40, prob = 0.10)   # → 0.10676
pbinom(6, size = 40, prob = 0.10)   # → 0.90048
sqrt(40 * 0.1 * 0.9)               # → 1.897

Im Mittel 4 Fehler erwartet, Streuung 1,90. Die 6 Teile liegen 1,05 Standardabweichungen darüber.

6 von 40 sind bei 10 % Ausschuss ein völlig normales Ergebnis.

Jetzt du! (im Skript, Ctrl+Enter zeilenweise)

  1. Vorhersage zuerst: Wie viel wahrscheinlicher ist 1 Fehler als 2 Fehler bei n = 5, p = 0,1?
  2. Baue die OC-Tabelle für n = 20, c = 0 bis 3. Wo ist der Unterschied zu n = 10 am größten — und warum gerade dort?
  3. Kunde: „5 % Ausschuss, mindestens 99 % Akzept, höchstens 1 Fehler." Löse nach pbinom auf. Wie groß muss n mindestens sein, und was passiert mit dem Warenrisiko bei p = 0,15?

Typische Fehler — vier Stück

# 1. dbinom statt pbinom — "höchstens c" sind c+1 Faelle
dbinom(1, 10, 0.05)   # → 0.3151  nur "genau 1"
pbinom(1, 10, 0.05)   # → 0.9139  "0 oder 1"

# 2. lower.tail = FALSE vergessen
pbinom(1, 5, 0.1)                     # → 0.9185  hoechstens 1
pbinom(1, 5, 0.1, lower.tail = FALSE) # → 0.0815  mindestens 2

# 3. "Mehr pruefen macht das Risiko kleiner" — nein!
pbinom(2, n, 0.05)   # n=10: 0.9885  n=20: 0.9245

# 4. Normalverteilung verwechselt
#    "6 von 40 ausserhalb" → binomial
#    "zwischen 9.98 und 10.02" → pnorm()
