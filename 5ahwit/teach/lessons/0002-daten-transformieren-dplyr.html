Lektion 0002 · UE 2 · 5AHWIT

Wiegen, was zählt: Daten transformieren

filter, mutate, summarise — und die Pipe, die sie verbindet.

Lektüre

R4DS 2e (englisch, Kap. 3 Data transformation) — lies Kapitel 3 vor der Hausaufgabe. Die HA-Fragen beziehen sich auf das Kapitel: Hausaufgabe UE 2.

Einstiegsfrage

Von der letzten Lektion kennst du die Pinguine. Jetzt wird es betrieblich: Wie schwer ist eine „typische" Pinguin-Art — und unterscheidet sich das nach Geschlecht?

Mit Plots allein antwortet man darauf vage („irgendwie schwerer"). Mit dplyr antwortest du mit einer Zahl — und Zahlen kann man gegen Toleranzen und Grenzwerte prüfen. Genau das brauchst du, wenn wir bald Versuchsdaten auswerten.

Ziel-Artefakt
penguins |>
  filter(sex == "female") |>
  group_by(species) |>
  summarise(gewicht_g = mean(body_mass_g, na.rm = TRUE))
# → 3 Zeilen: Adelie 3369, Chinstrap 3527, Gentoo 4680 (gerundet)

Drei Verben, drei Zeilen Ausgabe, eine saubere Antwort. Der Win von heute: Du liest diese Pipe vor dir her und weißt ohne Ausführen, was sie tut.

Verb 1 — filter (Zeilen wählen)

penguins |> filter(species == "Gentoo")
# → nur Gentoo-Zeilen: von 344 auf 124

filter() behält, was die Bedingung erfüllt. Achtung: Vergleichen macht == (gleich), zuweisen macht <-. Ein einzelnes = ist hier ein Fehler.

Wie viele Zeilen behält filter(species == "Gentoo", sex == "male")?

Mehrere Bedingungen in filter() verknüpft dplyr mit „UND" — jede Bedingung muss erfüllt sein.

Verb 2 — mutate (Spalten umformen/neu)

penguins |> mutate(gewicht_kg = body_mass_g / 1000)
# → alle 344 Zeilen + eine neue Spalte ganz rechts

mutate() (umformen) rechnet Spalte für Spalte: aus Gramm Kilogramm, aus Millimeter Zoll, aus zwei Werten eine Differenz. Bestehende Spalten bleiben unangetastet.

Verb 3 — summarise + group_by (schrumpfen)

summarise() (zusammenfassen) macht aus vielen Zeilen eine: Mittelwert, Minimum, Anzahl. Mit group_by() davor geschieht das pro Gruppe:

penguins |>
  group_by(species) |>
  summarise(gewicht_g = mean(body_mass_g, na.rm = TRUE))
# → 3 Zeilen (eine pro Art) statt 1 Zeile für alles

Und das na.rm = TRUE? Ein einziger NA — und dein Mittelwert wäre auch NA. Warum? R weigert sich, über fehlende Werte hinwegzumitteln, ohne dass du es es erlaubst. na.rm = TRUE ist die Erlaubnis: „ignoriere die fehlenden."

Das Klebeband: die Pipe |>

Die Pipe (Rohrleitung) reicht das Ergebnis links an die Funktion rechts weiter — lesbar wie ein Satz:

penguins |>            # nimm die Pinguin-Tabelle …
  filter(sex == "male") |>     # … behalte die Männchen …
  group_by(species) |>         # … gruppiere nach Art …
  summarise(gewicht_g = mean(body_mass_g, na.rm = TRUE))
# … und fasse je Gruppe zusammen.

Ohne Pipe sähe das aus wie Plätzchen in Plätzchen: summarise(group_by(filter(penguins, …)), …) — von innen nach außen, schwer lesbar. Mit Pipe liest man von oben nach unten.

Jetzt du!
  1. Vorhersage zuerst: Wie viele Zeilen hat penguins |> filter(flipper_length_mm > 210)? Erst raten und notieren, dann ausführen.
  2. Baue die Ziel-Pipe um auf Männchen und Spaltenname gewicht_kg (in Kilogramm, via mutate).
  3. Vorhersage: Was passiert mit der Ausgabe, wenn du na.rm = TRUE weglässt? Prüfe deine Vorhersage.
Typische Fehler

= statt == im filter

penguins |> filter(species = "Gentoo")
# ✗ "Filter expression must refer to ..." — Vergleichen ist ==

Filter-Ergebnis gespeichert — geglaubt

penguins |> filter(species == "Gentoo")
# → zeigt 124 Zeilen an, aber penguins ist UNVERÄNDERT

Ohne Zuweisung (gentoo <- …) verändert dplyr nichts — das Ergebnis verpufft im Bildschirm. dplyr arbeitet unveränderlich: gut so, aber merken.

Zusammenfassung

VerbWofür
